# LazyVidEditor

A quick little node app that creates streams from three separate systems to create a comprehensive log of live events. Those three Systems: OBS Websockets, Q-SYS telnet and finally an Extron Telnet. Hoping to eventually log from a Sony Visca serial link as well.

Has a Python Video editor, based on moviepy, and a Powerhell Log Parser!

## Overall Architecture

LazyVidEditor uses a combination of technologies to achieve its goal of semi-automated video editing:

*   **Node.js:** Used for logging data from OBS (via WebSockets), Q-SYS (via Telnet), and Extron (via Telnet) systems. It captures events like scene changes, microphone mutes, and other system states.
*   **PowerShell:** Employed for initial log parsing and batch video processing. It takes the raw logs from the Node.js components and processes them to identify video segments.
*   **Python:** Utilized for more advanced video editing tasks, including scene-based editing with `moviepy`, automatic subtitle generation using Google's Speech API, and log parsing. The `python-editor/log_parser.py` script offers a Python-based alternative to the PowerShell script for parsing aggregated log files, as a step towards workflow consolidation.

## Main Components/Scripts

### Node.js Loggers

These scripts are responsible for capturing data from various sources:

*   **`q-systest-beta.js` (and similar Q-SYS loggers):** Connects to a Q-SYS audio DSP via Telnet to monitor and log control changes, such as microphone mute states. Events are typically timestamped and saved to text files (e.g., `qsys-log.txt`).
    *   The Q-SYS Telnet protocol details can be found [here](http://q-syshelp.qschome.com/Content/External%20Control/Q-SYS%20External%20Control/007%20Q-SYS%20External%20Control%20Protocol.htm).
    *   Uses the `telnet-stream` module for communication.
*   **`extron-test.js` (and similar Extron loggers):** Connects to an Extron video switcher or control processor via Telnet to log events like input switches. Events are timestamped and saved to text files (e.g., `extron-log.txt`).
*   **OBS Loggers (e.g., through `obs-websocket-js` or custom implementations):** Connect to OBS Studio via WebSockets to log scene changes, transition events, and potentially other OBS states. This data is often saved to files like `obs-log.txt` or `infowriterlog.txt`.

The primary output of these loggers is a set of timestamped text files (often named `*-Slides.txt` or similar, depending on the specific logger's configuration) that record the state changes from each system.

### PowerShell Script (`Parse-badlog.ps1`)

This script takes the aggregated log files generated by the Node.js components and performs the following:

*   **Log Aggregation & Parsing:** Combines and processes logs from Q-SYS (mic activity) and potentially other sources like Extron or OBS.
*   **Segment Identification:** Identifies video segments primarily based on microphone activity (mute/unmute events). It may also consider slide changes or other events from the logs.
*   **Batch File Generation:** Creates batch files (`.bat`) containing `ffmpeg` commands. These commands are designed for:
    *   Initial video cuts based on the identified segments.
    *   Creating preview clips of these segments.
    *   Concatenating relevant segments into a rough cut of the final video.
    *   A Python-based alternative, `python-editor/log_parser.py`, has also been developed to parse these logs, offering a path towards consolidating this parsing logic within the Python ecosystem.

### Python Video Editor (`python-editor/scenetest_friday.py`)

This Python script leverages the `moviepy` library for more sophisticated video editing tasks:

*   **Scene-Based Editing:** Uses an OBS log file (`infowriterlog.txt`, which specifically logs OBS scene changes with timestamps) to drive the editing process.
*   **Capabilities:**
    *   **Compositing:** Combining multiple video clips or sources.
    *   **Overlays:** Adding graphics, text, or other visual elements.
    *   **Lower Thirds:** Generating and displaying lower third graphics.
    *   **Transitions:** Applying transitions between scenes (though capabilities might depend on `moviepy` features and script implementation).
*   It may also use `imagemagick` for image manipulation tasks related to graphics or overlays.

### Python Subtitle Generator (`python-editor/autosub_app.py`)

This script automates the process of generating subtitles for videos:

*   **Audio Extraction:** Uses `ffmpeg` to extract the audio track from a video file.
*   **Speech-to-Text:** Sends the extracted audio to the Google Speech API to convert spoken words into text.
*   **Subtitle File Generation:** Creates subtitle files (e.g., `.srt` format) from the transcribed text.
*   Note: This script appears to be written for Python 2.7, given its syntax (e.g., `print` statements without parentheses).

## Known Limitations / Future Work

Based on code comments and analysis, the project has several areas for improvement:

*   **Video Synchronization:** Synchronizing video recordings from multiple cameras or sources with the logged events is a significant challenge.
    *   The script `python-editor/alignment_by_row_channels.py` exists but does not seem to be actively used in the main workflows.
    *   Current workflows often fall back to manual synchronization methods or rely on the accuracy of the timestamped logs.
*   **Hardcoded Paths:** Many scripts contain hardcoded file paths, IP addresses, and other configuration details. This makes the project less portable and harder to configure for different environments.
*   **Error Handling and Logging:** Robustness could be improved with more comprehensive error handling and detailed logging throughout the scripts.
*   **Experimental/Incomplete Scripts:** Some scripts, like `python-editor/pyaudioeditsinit.py`, appear to be experimental or incomplete.
*   **Disconnected Workflows:** The Python editing workflow (`scenetest_friday.py` using `infowriterlog.txt`) and the PowerShell workflow (`Parse-badlog.ps1` using aggregated logs) are somewhat disconnected. They use different primary log sources and cues for editing decisions.
*   **Potential for Consolidation:** Some PowerShell scripting functionalities could potentially be consolidated into Python or Node.js to create a more integrated and streamlined toolchain.
*   **Python 2.7 Dependency:** `python-editor/autosub_app.py` was originally written for Python 2.7 but has now been updated for Python 3 compatibility. Other scripts like `scenetest_friday.py` may still require further updates for full Python 3 support.

## Setup & Running (High-Level)

To set up and run LazyVidEditor, you'll generally need the following:

*   **Node.js:** Install Node.js to run the logger scripts.
*   **Python:** Python 3 is now recommended. `python-editor/autosub_app.py` has been updated for Python 3. While `scenetest_friday.py` has received some Python 3 updates (related to config loading), it and other scripts may still contain Python 2 syntax (e.g., `print` statements) and require further review for full Python 3 compatibility.
    *   **Python Packages:** Install necessary packages using `pip`. Common packages include:
        *   `moviepy`
        *   `google-api-python-client`
        *   `requests`
        *   `progressbar`
        *   (Potentially others, check script imports)
*   **PowerShell:** Available by default on Windows systems.
*   **`ffmpeg`:** Must be installed and accessible in your system's PATH. This is crucial for both PowerShell and Python video processing.
*   **`imagemagick`:** Required for certain features in `python-editor/scenetest_friday.py`. Must be installed and accessible in your system's PATH if those features are used.
*   **API Keys:** For `python-editor/autosub_app.py`, you will need API keys for the Google Speech API (and potentially Google Translate API if that functionality is used). These need to be configured correctly for the script to work.
*   **Configuration:**
    *   Device IP addresses (for Q-SYS, Extron, OBS) are often hardcoded in the Node.js logger scripts and will need to be adjusted to match your network setup.
    *   File paths for logs, video files, and output directories are hardcoded in many scripts and will require modification.

This project provides a foundation for automating parts of the video editing workflow, particularly for event recordings. However, be prepared to modify scripts and configurations significantly to adapt it to your specific environment and needs.
